# Навчальний Блокчейн (ПЗ № 1)

Власна реалізація блокчейну з консенсусом Proof of Work, деревом Меркла, чергою транзакцій (Mempool), P2P-мережею вузлів та механізмом розв'язання форків за правилом найбільшої кумулятивної роботи.

## Вимоги

- Node.js (v20 або новіша)
- pnpm
- Docker & Docker Compose (опціонально, для кластера з 5 нод)

## Встановлення

```bash
pnpm install
```

## Основні команди

### 1. Автоматичні тести (32 тести)
Покривають криптографію, дерево Меркла, мемпул, блокчейн, стійкість до 5 атак та консенсус:
```bash
pnpm test
```

### 2. Симуляція 5 атак
Демонструє відхилення системою спроб компрометації (зміна суми, підміна блоку, підроблений підпис, подвійна витрата, replay attack):
```bash
pnpm run attacks
```
Для запуску конкретної атаки (наприклад, атаки 2):
```bash
pnpm run attacks 2
```

### 3. Експеримент складності майнінгу
Вимірює час знаходження PoW для 5 рівнів складності (по 10 запусків на кожен рівень), зберігає дані у `benchmark_results.json` та генерує векторний графік `mining_benchmark.svg` із логарифмічною віссю часу:
```bash
pnpm run benchmark
```

### 4. Автоматична демонстрація мережі з 3 вузлів та форку
Запускає 3 вузли на портах 3001, 3002, 3003, створює штучне розгалуження (форк), демонструє перехід на гілку з більшою роботою та повернення осиротілих транзакцій у мемпул:
```bash
pnpm run demo:network
```

### 5. Ручний запуск 3 вузлів одночасно
Запускає три незалежні процеси вузлів на портах 3001, 3002, 3003:
```bash
pnpm run nodes:start
```
Або безпосередньо через bash-скрипт:
```bash
./scripts/start_nodes.sh
```

### 6. Запуск кластера з 5 вузлів у Docker Compose (Додаткове завдання)
Запускає 5 ізольованих контейнерів вузлів у спільній bridge-мережі `blockchain-net` на портах 3001–3005:
```bash
pnpm run docker:up
```
Перегляд логів у реальному часі:
```bash
pnpm run docker:logs
```
Зупинка та видалення контейнерів:
```bash
pnpm run docker:down
```

## REST API вузла

Кожен вузол надає REST API для керування та P2P-комунікації:

| Метод | Шлях | Опис |
|---|---|---|
| `POST` | `/wallet` | Створення нового гаманця (повертає адресу, публічний та приватний ключі) |
| `POST` | `/transactions/sign` | Допоміжний ендпоінт створення Ed25519-підпису транзакції |
| `POST` | `/transactions` | Додавання підписаної транзакції до мемпулу та broadcast усім сусідам |
| `GET` | `/balance/:address` | Отримання балансу та поточного nonce адреси |
| `GET` | `/mempool` | Перегляд непідтверджених транзакцій у черзі |
| `GET` | `/chain` | Отримання повної історії блоків та кумулятивної роботи |
| `GET` | `/chain/validate` | Повна валідація ланцюга (хеші, Merkle roots, підписи, nonces) |
| `POST` | `/mine` | Майнінг нового блоку з транзакцій мемпулу + coinbase |
| `POST` | `/blocks` | Отримання та обробка нового блоку від піра |
| `GET` | `/peers` | Список відомих адрес сусідніх вузлів |
| `POST` | `/peers` | Додавання нової адреси сусіда |
| `DELETE` | `/peers` | Відключення сусідів (очищення пірів) |
| `POST` | `/sync` | Запит синхронізації з сусідами за правилом найбільшої роботи |

## Тестування через Postman

У корені проєкту знаходиться готова колекція запитів [`blockchain.postman_collection.json`](./blockchain.postman_collection.json), яка містить готові сценарії для:
1. Отримання ланцюга (`GET /chain`)
2. Генерації гаманця (`POST /wallet`)
3. Майнінгу стартових монет (`POST /mine`)
4. Перевірки балансу (`GET /balance/:address`)
5. Підпису транзакції (`POST /transactions/sign`)
6. Відправки підписаної транзакції в мережу (`POST /transactions`)
7. Перевірки ретрансляції транзакції по P2P в Mempool сусідніх вузлів (`GET :3002/mempool`)
8. Майнінгу на іншому вузлі та синхронізації балансу по всій мережі
